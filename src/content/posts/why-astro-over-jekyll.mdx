## Decision

This site uses Astro instead of Jekyll because the blog is not only a publishing surface. It is also a developer showcase and an AI-readable content repository.

Astro gives this project MDX, content schema validation, static output, and component-level control without requiring a runtime server.

## Tradeoff

Jekyll remains a strong choice for a simple GitHub Pages blog. The cost is that Ruby, Liquid, and weaker content typing do not fit this repo's current direction as well.

Next.js would make full-stack experiments easier, but it is too much machinery for v1.
